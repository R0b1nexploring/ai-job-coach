# 第 18 节基线：岗位写作与项目资源边界（2026-09-19）

对应 tasks 18.1。本记录是收窄范围后的实施基线，只描述实测现状，不代表任何任务已完成。

## 用户目标（本次裁决）

只做三件事：

1. 生成的（虚构）项目经历不要超出用户自身的水平，不凭空出现实验室、专业仿真或量产成果。
2. 项目经历要结合用户自己提供的个人信息（专业、课程、工具、已有经历）来优化。
3. 让用户大致看懂「投这个岗位，一段像样的项目经历大概长什么样」。

不建设 `writing_strategy` 完整字段体系、策略独立指纹、策略语义过期反向规则或规则版本进 request hash。
第 18 节原规格中超出以上目标的机制性要求按本基线收窄。

## 当前实现（实测）

| 项 | 现状 |
| --- | --- |
| 选材 | `build_writing_brief` 按词项重合打分，取前 3，输出 `selected_materials` 与 `matched_requirement_ids` |
| 项目输入 | `build_project_story_inputs` 把选中素材转成 writer 输入，含 `story_boundary` 与 `design_supplement` |

## 真实模型对照（同一虚构本科素材，两个机械方向 JD）

素材：减速箱 SolidWorks 建模+装配+工程图；工训中心车削/钻削实训；公开手册联轴器选型报告。
无实验室、无仿真软件、无工厂实习。

- 机械结构设计 JD：结构方案设计与三维建模 / 输出装配体与工程图 / 解决干涉与配合。
- 机械工艺 JD：编制工艺路线与工序卡 / 确定加工参数与工装 / 首件检验与过程检查。

结果（`deepseek-v4.1-flash`，本地 OpenAI 兼容桥）：

| 观察 | 结论 |
| --- | --- |
| 选材顺序 | 随 JD 改变（结构岗设计素材 216 分第一；工艺岗实训素材 72 分第一，设计素材降到 16） |
| 求职版正文 | **两个 JD 的 3 条要点逐字相同、顺序相同** |
| 蓝图版正文 | 前 3 条相同，仅末尾目标缺口不同 |
| 资源边界 | 未编造实验、专业仿真或量产成果（符合要求） |
| 本科水平 | 未因学历降低有依据的经历（符合要求） |

结论：选材排序已随 JD 变化，但**写作角度与篇幅没有变化**，仍停留在「换关键词」层面。
真实缺口是「策略 → 正文表达」的传递，不是缺少策略字段。

## 本次要修的缺口

1. **无个性化输入**：项目生成不知道用户学过什么、用过什么工具、做过什么，只能靠目标要求空想。
2. **无资源检查**：写作提示是软约束，没有本地拦截；`achieved=false` 只标记未达成，不能阻止方案本身依赖不可得资源。
3. **传递链路**：选材结果没有告诉 writer「这段素材证明哪项要求、该展开还是压缩」。

## 已知的次要问题（本次一并修）

`CATEGORY_SECTIONS` 的合法类别是 `education/employment/projects/skills/certificates/other`。
传入未知类别（例如 `internships`）会静默落到「项目/科研/竞赛」分区，导致实习经历被归到项目区。
本地兜底路径 `_fallback_version` 与 `_canonical_section` 都有这个默认值。

## 验证方式

- 合同测试：资源检查、个性化输入、选材理由（mock）。
- 真实模型对照：同一素材两个 JD，人工核对项目水平是否合理、是否贴合本人、两岗位是否有可解释差异。
- 真实模型证据与 mock 分开记录；无真实改善证据的任务保持未完成。

## 真实模型结果（2026-09-19）

**机械结构设计 JD：通过，效果符合目标。**

真实模型输出了贴合本人素材的蓝图项目，水平合理、无越界：
求职版按 JD 重组为三维建模 / 配合约束与装配 / 装配体与工程图 / 选型比较四组要点；
蓝图版在此基础上追加三条「待补充」目标（干涉检查、尺寸公差标注、选型结论落到周边结构），
全部带 `*` 且 `achieved=false`。未出现实验室、仿真或量产内容。

**机械工艺 JD：Provider 阻塞，未取得真实输出。**

该 JD 的 writer 调用返回 `LLM_MALFORMED_RESPONSE:truncated`，回退到本地模板。
排查结论是本地桥的模型问题，不是产品缺陷：

```
finish_reason=length, content_len=0, reasoning_tokens=2048(=max_tokens)
```

本地桥 `deepseek-v4.1-flash` 会把整个输出预算消耗在 reasoning tokens 上并返回空 content；
把 `max_tokens` 提到 8192 仍是 `reasoning_tokens=8192`、content 为空。
该桥不支持 `reasoning_effort`（返回 `UnsupportedParamsError`），无法降低推理量。

因此**「同一素材两个 JD 都有真实改善」这一条没有取得证据**，18.4 保持未完成。
结构设计侧的改善是真实模型结果，但不是双岗位对照，不能单独作为策略有效性验收。
