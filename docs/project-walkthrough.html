双版本生成、局部重写与幂等

双版本生成编排（bundle_service）

process_bundle() 是核心编排函数，执行以下步骤：

  1. 原子 claim：通过带租约的数据库更新原子抢占运行权，claim token 只保存在 worker 内部；90 秒未续租的 generating 任务可被恢复。
  2. LLM 写入双版本：分别调用 _write_version() 生成 submittable 和 target。系统提示词明确允许 AI 扩写，要求补充内容设 verification_status=ai_generated、achieved=false。
  3. 质量评审：每份版本调用 evaluate_version_with_critic()（确定性硬门禁 + 可选 LLM 七维评分）。
  4. 修复循环（最多 2 轮）：硬门禁未通过的版本用确定性 fallback 重写后重新评审。任一回退触发 degraded 标记。
  5. 终态判定：
    • submittable 必须 hard_passed，否则整个 bundle failed
    • target 若仍不通过，调用 _omit_ungrounded_future() 移除无来源未来项后降级为 degraded
  6. 持久化：_upsert_version() 写入/更新两份 ResumeVersion，计算 content_hash，保存 quality_report 和 template_snapshot。
  7. 自动生成面试指南：bundle 达到 ready/degraded 后，调用 generate_guides_for_bundle() 为每份版本创建 InterviewGuide。

选择性重生成

scope行为
bullet只重写指定 bullet_id，保留其 id 和来源字段。已锁定（locked=true）的 bullet 拒绝重写（409）。
section只重写指定分区，其余分区保持原结构。锁定条目在重写后通过 _merge_locked() 恢复。
all整份重生成，但通过 _merge_locked() 保留所有 locked bullet 的原文和位置。

重生成后若 content_hash 变化，关联的 InterviewGuide 自动标记为 stale。

幂等与额度

  • 默认幂等键 = resume-bundle:{user_id}:{resume_id}:{profile_id}:{payload_hash}，也支持客户端通过 Idempotency-Key 头自定义。
  • 同一幂等键不同 payload 返回 409。
  • 生成消耗 1 点 resume 额度，通过 quota_ledger 记录。
质量门禁与解释性评分

质量门禁机制（quality_service）

硬门禁（阻止交付）

  • 来源归属：bullet 引用的 source_fact_ids / requirement_ids 必须存在于当前生成上下文中，否则「引用了不属于当前生成上下文的来源」。
  • kind 一致性：content.kind 必须与生成模式匹配。旧 strict 模式限制未达成项；当前 ai_expansion 模式允许 AI 扩写内容，仍校验来源 ID 归属与结构。
  • 蓝图覆盖率：target 模式下，所有 high priority 要求必须被引用或在文本中覆盖，否则「蓝图未覆盖高优先级目标要求」。
  • 分区顺序：sections 顺序必须符合模板定义（教育背景 → 实习/工作 → 项目/科研/竞赛 → 奖项证书 → 技能）。
  • 单页预算：估算行数 ≤ 48 行（按字符数估算），超出则「超过单页内容预算」。
  • headline 非空：求职方向不能为空。
  • 可校验条目：简历内容必须至少有一条可校验 bullet。

解释性评分（不阻止交付）

LLM critic 可选调用，失败时回退确定性评分。七个维度各 0-100 分：

维度确定性评分逻辑
target_relevance高优先级要求覆盖率 = 100 × (1 - 未覆盖数 / 高优先级总数)
specificity有数字则 70，否则 60
personal_contribution有「本人」或 source_fact_ids 则 80，否则 55
information_densitymin(100, 40 + 8 × bullet 数)
readability固定 75
ats固定 80
interview_defensibilitysubmittable 70，target 65
critic 不能覆盖硬门禁：apply_critic_cannot_override() 确保即使 LLM 给了高分，只要 hard_passed=false，状态仍为 blocked。LLM 只提供解释性评分和改进建议。

ai_expansion 模式下的 Fact Guard 角色转变

在 factuality_policy=ai_expansion 时，Fact Guard 的结果不再作为交付否决，而是作为「来源诊断」：

  • 引用了不存在的来源 ID → 仍为硬 issue（阻止交付）
  • 缺少事实支持 / 实体不在来源中 / 中文主张无来源 → 降级为 warning，自动将该 bullet 设为 verification_status=ai_generated、achieved=false，并记录「AI 扩写内容，未绑定用户事实来源」
  • 经历条目的 header（organization/role_title 等）若不在引用事实中，也触发 ai_generated 标记
两类指南与覆盖率

面试指南（InterviewGuide）

新 InterviewGuide 与旧 Interview 表完全分离。第一阶段不提供答题、评分或语音模拟，只提供准备材料。

求职版作战指南 (submittable)

  • 60 秒 / 90 秒自我介绍
  • JD 专业与行为题
  • 岗位动机说明
  • 向面试官的反问
  • 面试前检查表
  • 每条 bullet → 一张卡片：
    • 主问题 + 连续追问
    • 六段式讲法（背景/目标/行动/工具/结果/收获）
    • 个人贡献边界
    • 核验材料提示
    • 危险说法警示
  • AI 补充条目自动加 honest_boundary

蓝图风险指南 (target)

  • 只覆盖 achieved=false 的条目
  • 每张卡片：
    • 可能被问穿的问题
    • 诚实边界（不能声称已完成）
    • 缺少的证据
    • 补齐后的答法
  • completed_as_done: false（明确标记未完成）
  • 核心原则：等补齐证据后再用真实过程回答，而不是现在排练假经历

覆盖率校验

LLM 生成的卡片必须覆盖所有 needed bullets（submittable 覆盖全部，target 覆盖未达成项）。缺失任何一条 → 回退通用模板。模板仍缺失 → 指南状态保持 queued，quality_report 标记 coverage_incomplete。

PDF 物理 QA（6 项检查）

  • 页数：必须恰好 1 页
  • 尺寸：必须 A4 纵向（595.28×841.89pt，±8pt 容差）
  • 裁切：CropBox 不得裁切 MediaBox；无文字超出页面边界

安全、隐私与用户隔离

安全与隐私设计

生产启动自检

  • JWT 密钥强度 ≥ 32 字节，禁止默认值
  • 必须 HTTPS（非 localhost 时）
  • 必须 PostgreSQL（禁止 SQLite）
  • 必须非默认管理员密码
  • Storage 必须非 local（需对象存储）

文件权限

  • .env 自动 chmod 600
  • SQLite 文件自动 chmod 600
  • uploads 目录自动 chmod 700

LLM 日志安全

  • 只记任务名/档位/模型/耗时/token 数
  • 不记简历原文或密钥
  • 错误信息过滤 prompt/raw_jd/password/api_key

public_jsonld 七层防护

  • 仅 HTTPS / 443 端口
  • 拒绝 IP 字面量 URL
  • DNS 解析必须为公网地址
  • 不跟随重定向
  • robots.txt 检查
  • 2MB 响应截断
  • Content-Type 白名单

数据保留与删除

  • 账号删除后数据保留 180 天（可恢复窗口），之后进入 7 天删除宽限期，由 storage_deletion_tasks 跟踪。
  • 用户可申请数据导出（JSON 格式）。
  • 所有写操作记录 audit_logs。

跨用户隔离

所有查询通过 current_user 依赖注入获取用户身份，服务层的 owned_* 函数（owned_bundle / owned_profile / owned_guide 等）强制校验 user_id 匹配，不匹配返回 404。测试覆盖跨用户越权访问场景。
