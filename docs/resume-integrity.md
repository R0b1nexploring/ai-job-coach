# 简历事实保护与审核规则

## 目标

系统允许用户纠正、补充和完成新的真实经历，但不把表达优化变成履历虚构。产品同时提供“学习靶子”和“当下可投递内容”：AI 负责结构化改写，用户负责确认事实和完成产出物，系统负责逐条标记与校验来源，顾问负责最终交付质量。

## 可以修改和补充的内容

- 修正简历解析错误、时间格式和遗漏字段；
- 补充用户真实完成但原简历未写的职责、工具和结果；
- 加入之后真实完成的个人项目、课程项目、练习项目或公开案例复现；
- 在不改变责任程度和结果的前提下，用动作—任务—结果或 STAR 结构重写；
- 将有事实证据的 JD 关键词自然融入对应经历。

## 两类简历产物

| | 蓝图简历 `target` | 可投递简历 `submittable` |
|---|---|---|
| 内容来源 | 已确认事实与未达成学习目标 | 仅已确认事实 |
| 逐条状态 | 已达成，或明确 `achieved=false` | 全部 `achieved=true` |
| 溯源字段 | `source_fact_ids` 或 `source_target_ids` | `source_fact_ids` |
| 用途 | 明确要补到什么水平，并驱动学习 | 反映用户当下真实水平 |

蓝图中的未达成条目不是已验证事实，必须在页面、HTML 和 DOCX 中显示“未达成 · 学习目标”。蓝图是否投递由用户决定，系统不做硬阻断，但投递前只提示一次未达成清单，面试指南也会明确指出暴露风险。

## 禁止伪装为已达成或进入可投递版本的内容

- 虚构公司、岗位、任职或实习时间，包括利用已倒闭公司降低核验概率；
- 把专业常见岗位或他人经历写成用户本人任职；
- 冒用他人的项目任务、个人贡献和量化成果；
- 虚构奖学金、比赛奖项、证书、排名和学院荣誉；
- 把“参与”扩大为“负责”或“主导”，或加入未经确认的数字、工具和结果；
- 为覆盖 JD 关键词而声称用户具备没有证据的技能。

上述缺口可以作为蓝图中的未达成学习目标，但不能写成已经拥有的经历、技能或成果。

## 经历补强工作流

当匹配报告发现能力缺口时，系统可以推荐一至两周可完成的实践任务，例如 AI 应用、数据库部署、数据清洗或业务工作流。任务应包含：

1. 明确的目标岗位要求；
2. 用户需要亲自完成的任务清单；
3. 可核对的产物，如代码、提交记录、部署说明、截图、测试或演示地址；
4. 用户实际贡献和参考来源；
5. 完成后可进入事实库的候选要点。

未完成前，任务只进入蓝图并标记未达成。用户亲自完成产出物、提交证据并确认后，系统创建 `provenance=learned` 的事实；此后才可进入可投递版本。简历中使用“个人项目”“岗位实践”“课程项目”或“案例复现”等真实标签，不写成公司实习。参考公开方案时使用“参考并复现”“在原方案基础上修改”等准确表述。

## 事实状态

| 状态 | 含义 | 可否用于正式版本 |
|---|---|---|
| `extracted` | 系统从文件中提取，用户尚未确认 | 否 |
| `proposed` | AI、顾问或实践任务建议补充 | 否 |
| `user_confirmed` | 用户确认真实并愿意为其负责 | 可以进入可投递 Fact Guard |
| `user_rejected` | 用户确认不准确或不使用 | 否 |

用户确认不代表顾问已经验证证书或雇佣关系。产品展示时必须区分“用户声明”“材料可核对”和“顾问审核表达”，不使用“官方认证”等误导性措辞。

## 审核流程

```text
事实库确认 + 匹配缺口
→ 生成学习目标
→ 生成蓝图或可投递简历
→ mode-aware Fact Guard 逐条检查来源、状态、数字、工具和新增主张
→ 用户提交顾问审核
→ 顾问批准或退回
→ 批准后导出并进入投递队列
```

- 普通用户不能自行将版本设为 `approved`；
- Fact Guard 为 `blocked` 时不能提交或批准；
- 顾问只能查看和审核被分配的客户；
- 可投递要点必须保留 `source_fact_ids`；蓝图未达成要点必须保留 `source_target_ids` 和 `achieved=false`；
- 未批准版本不能导出或进入投递队列，但批准后的蓝图不会仅因存在未达成条目而被禁止；
- 审核、批准、退回和导出属于应记录的关键操作。

## 面试可追问原则

每个已达成要点都应能回答：背景是什么、用户具体做了什么、为什么这样做、实际结果是什么、有哪些产物可以展示。未达成蓝图条目必须在面试指南中给出诚实说明和高风险追问；无法回答或只能复述他人经验的内容，应继续作为实践任务，不能进入可投递简历。系统生成的投递邮件正文同样只引用已确认事实，即使用户选择把蓝图作为附件也不例外。
