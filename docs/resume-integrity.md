# 简历事实保护规则

## 目标

系统可以重写、压缩和重排用户原简历，但不能把表达优化变成履历虚构。

## 允许

- 调整顺序以突出与 JD 相关的真实内容；
- 压缩重复表达；
- 在不改变责任程度和结果的前提下优化措辞；
- 将原简历已经出现的工具和关键词放到更相关的位置；
- 把没有来源支持的 JD 要求列为能力缺口。

## 禁止

- 新增公司、岗位、任职、实习或项目；
- 新增日期、证书、奖项和排名；
- 新增原简历中不存在的工具、成果和数字；
- 把参与扩大为负责、主导或独立完成；
- 把团队成果写成个人成果；
- 为覆盖 JD 关键词而声称用户具备没有来源的技能。

## 来源状态

上传后提取的简历行保持 `extracted` 状态，不自动变成 `user_confirmed`。单页流程允许这些原文来源生成建议稿，但必须同时满足：

1. 每个输出要点具有 `source_fact_ids`；
2. Fact Guard 能在同一用户的原简历来源中找到引用；
3. 新出现的数字、工具、证书或成果会被拦截；
4. 页面和下载文件明确标注“建议稿，请逐项核对”。

Fact Guard 通过只表示输出没有超出机器可追溯的输入范围，不表示学校、雇佣关系、证书或个人贡献已经被独立验证。

## 面试原则

面试引导只能引用相同的原简历来源。用户应能解释每段经历的背景、个人行动、实际产物和复盘；无法确认的内容应删除，而不是临场补造。
