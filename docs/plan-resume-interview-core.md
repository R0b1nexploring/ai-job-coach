## 0. 产品决策

> **2026-09-05 用户最新裁决：允许 AI 扩写。** 新生成的工作台 v3 简历采用 `factuality_policy=ai_expansion`，允许超出已确认事实补充内容，也允许仅凭目标画像创建草稿。缺少事实支持、新主张和未达成状态不再阻止生成、预览或导出；来源 ID 归属、结构及版面仍需通过检查。AI 补充记录 `verification_status=ai_generated`、`achieved=false`，在工作台、导出和指南标识待核验，不自动写入已确认事实库。`submittable` 的界面名称改为“求职版”。本裁决覆盖本文此前相冲突的事实限制；旧 v1/v2 接口保持兼容。

1. **一个不分年级的自助流程**。主路径是「单个 JD 或多 JD 画像 → 上传简历或空白建档 → 结构化素材与 AI 追问 → 同源双轨简历 → 三格式导出 → 两份面试指南」。
2. **目标画像是唯一目标合同**。`single_jd` 恰好一份 JD，`multi_jd` 为 2–10 份。每项要求必须带来源 JD 和原文证据。旧 Match 可作辅助解释，但不再是创建双轨简历包的前置条件。
3. **求职简历允许 AI 扩写**。可超出已确认事实补充组织、职责、工具、成果等内容，保留 AI 待核验标识；没有已确认素材也可基于目标画像生成草稿。
4. **蓝图 Plus 必须可见未达成状态**。每个未来要点保持 `achieved:false`、正文显示轻量 `*`，页脚解释该标记表示尚未形成可核验经历。
5. **自动质量门禁替代顾问批准**。事实支持检查改为提示，预览和导出要求来源归属、结构与版面硬门禁通过。`degraded` 可带工作台警告导出，硬门禁失败不得交付。
6. **第一阶段指南只用于准备，不用于练习**。分别为求职版和蓝图生成逐条指南；不提供答题、评分或语音模拟。
7. **旧能力保留兼容接口**。岗位看板、投递、学习目标、顾问运营和套餐额度退出普通用户主导航，但不删除旧 URL 与已授权 API。

## 2. 阶段顺序

1. **基线**：前端可构建；仓库忽略个人 PDF、JD dump、`var/`、`tmp/`、`output/`。
2. **Alembic `0009`**：目标画像 / 来源表；扩展素材 kind、详情、追问、确认状态；事实增加 `material_id` / `claim_type` / `evidence_json`。
3. **目标画像与素材 API**：校验 JD 数量、证据子串、用户隔离、空白建档、解析预填、原子确认、编辑后过期。
4. **Alembic `0010`**：`resume_bundles`、生成运行记录、`interview_guides`；`ResumeVersion` 增加 bundle / 画像 / 质量报告 / 内容哈希 / 模板快照，`job_id` 可空。
5. **双轨生成**：创建接口返回 202；进程内 worker；规划 → 写作 → Fact Guard → 质量评审 → 最多两轮修复 → 排版 QA；幂等复用；局部重生成尊重锁定。
6. **导出**：应用内 `classic-navy-ats-v2` 快照；HTML 为规范布局；DOCX / PDF 同源；PDF 优先 Chromium，其次 LibreOffice；蓝图 `*` 与页脚。
7. **面试指南**：bundle ready 后为两版排队；覆盖率 100%；内容哈希变化后旧指南 stale。
8. **工作台**：`/app/resume-studio` 成为普通用户默认入口；主导航只保留工作台、指南、账户设置。
9. **验收**：四类理工科虚构基准、迁移、自动门禁、导出 QA、完整自助 E2E。真实授权材料不得进入仓库、日志或固定测试。
