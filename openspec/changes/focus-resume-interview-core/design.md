> **2026-09-05 用户最新裁决：允许 AI 扩写。** 新生成的工作台 v3 简历采用 `factuality_policy=ai_expansion`，允许超出已确认事实补充内容，也允许仅凭目标画像创建草稿。缺少事实支持、新主张和未达成状态不再阻止生成、预览或导出；来源 ID 归属、结构及版面仍需通过检查。AI 补充记录 `verification_status=ai_generated`、`achieved=false` 作为内部来源状态，但在工作台、导出和指南不显示“待核验”标记，不自动写入已确认事实库。`submittable` 的界面名称改为“求职版”。本裁决覆盖本文此前相冲突的事实限制；旧 v1/v2 接口保持兼容。

## Context

现有主应用以 `Job + Match + ResumeVersion` 为中心，简历生成依赖单个岗位和已确认事实；`target/submittable`、逐条来源和 Fact Guard 已存在。经历库只覆盖实习/项目，面试记录同时承担题组、作答和顾问评分，主应用只导出 HTML/DOCX，而更完整的 PDF/QA 位于根目录旁路。新方向需要在保留旧数据与接口的前提下，把这些能力收敛为一个无需顾问介入的简历工作台。

约束包括：AI 文本不能成为已验证事实；未达成蓝图条目必须保持 `achieved:false` 且在渲染中可识别；真实简历、密钥和完整个人材料不得进入日志、测试夹具或 Git；外部 LLM 必须继续有本地安全回退。

## Goals / Non-Goals

> **2026-09-12 执行范围覆盖：** 本轮只主动推进蓝图项目 STAR 与同源指南，顺序见下方新决策及 tasks 第 15 节。既有用户修改合同保留兼容、后续完善；岗位信息建设、邀请试用上线、原型库实验和独立排版改版暂缓。不新增阶段完成条件或发布分数阈值。下文历史设计不构成自动扩大本轮范围的依据。

**Goals:**

- 用一个目标画像统一单 JD 与多 JD 生成，并让每项要求可回溯到输入 JD。
- 用结构化素材和原子事实提高可改写空间，同时比现有整段文本 Guard 更精确。
- 一次异步生成同源双版本、自动质量报告和两份逐条指南。
- 将一套模板、三种导出和 PDF QA 合并进主应用，并复现历史版本。
- 保留旧数据、v1/v2 内容和旧接口，逐步把用户流量切到新工作台。

**Non-Goals:**

- 按年级、学历阶段或求职阶段建立不同流程。
- 多模板市场、自由排版、英文简历、实时语音或文字模拟面试。
- 继续完善校招看板、职位聚合、投递管理、顾问工作台、套餐或支付。
- 把 AI 补充保存为已确认事实、隐藏蓝图未达成标记，或以面试指南训练用户冒充未完成经历；这不禁止求职版中的未确认 AI 扩写。

本轮边界修订不恢复早先的调用预算方案，不新增缓存、调用统计或策略开关，不要求画像免重复抽取、默认规则追问或按需指南。模型如何拆分写作与评审调用不属于本轮合同；指南继续按第 7 节自动排队。旧“两轮修复”不再是实施要求。

## Decisions

### 2026-09-16：内部项目方案、同源输出与模型评审

本决策细化第 15 节蓝图与指南工作。项目方案只作为系统内部材料，不新增项目教程、方案浏览或用户必填步骤。正式生成仍以有效 JD 画像为目标合同；“没有样本也可推进”指开发验收可以使用虚构 JD/画像和项目素材，不新增脱离 JD 的正式生成入口。

#### 内容顺序与存储

沿用 `project_story` 及版本内容 JSON：按项目汇集其事实、证据、草稿与目标要求 → 展开方案 → 压缩为可见简历 → 本地检查与模型评审 → 保存版本 → 同源指南。先方案后文案是逻辑依赖，不规定额外模型调用数，也不新建持久任务平台。

方案至少说明具体问题、个人目标、输入输出、行动步骤、方法取舍、关键难点、产物及验证方式。已有来源、设计补充与待验证问题明确区分。无素材/无项目库时允许 AI 设计简单项目；复杂内容缺资料时缩小范围，不能用编造的实施细节或实测指标补空。没有数字的程序、图纸、报告同样可作为结果，只要验证方式具体。

每个项目保留自己的证据上下文；STAR 各要素关联实际可见要点，关联存在只证明结构，不证明语义覆盖。项目方案随版本保存，方法、角色、目标、验证方式等语义变化进入内容哈希并使指南过期；旧无方案版本按现有兼容路径读取。若后续需要扩展 JSON 结构，版本化处理；只有数据库 schema 变化才需要迁移。

#### 评审分工与交付

保留求职版和蓝图版的模型 critic、分项评分和项目/要点级建议，复用现有 Provider。输入为各自实际正文、项目方案、事实、目标要求和本地诊断，不要求切换到另一模型。不给指南另增独立评分模型。

本地检查定位缺项、已知占位话术、错误归属、映射和状态；逐条检查行动与指标，不能一条完整就掩盖其他缺项。critic 检查项目与正文是否一致、行动能否解释结果、取舍和技术路线是否可解释。语义判断仍可能错误，不能以高分或无诊断证明经历真实、技术已验证或项目已复现。

保留现有边界：只有本地内容硬门禁失败触发定向修复，低分和风格建议不单独触发重写；评审不可用明确使用确定性检查并标记 degraded，内容硬门禁仍失败则 failed；PDF 失败继续隔离。质量诊断与内部元数据不混入简历正文。

指南从所绑定版本的方案与实际简历展开，不重新发明项目；缺失或未验证部分成为准备问题，既有实践准备保留，不能生成冒充完成的个人答案。求职版不借用蓝图未来成果。

#### 验证与后续项目库

先用虚构输入验证空白、稀疏、多项目和无数值结果，以及占位话术、因果矛盾、正文压缩丢失、来源隔离和指南一致性。规则/协议测试与真实模型效果对照分别记录；后者以同输入改动前后输出和人工检查为证据，不设固定样本数、统一评分阈值或模型自评分放行条件。

后续项目库复用同一项目详解概念，收集网上资料、参考简历中的项目模式及 AI 设计。按岗位推荐并允许替换，后端控制检索，公共模板、用户实例和已生成版本快照分开；具体数据库、采集器和选择界面不在当前实施任务中。网上资料的整理不等于复现，参考简历及 AI 补充不等于本人事实。

### 2026-09-12：蓝图 STAR 与同源指南

#### 数据组织与兼容

复用现有目标画像、素材快照、双版本内容及指南服务，不新增岗位采集或用户编辑模块。当前文案结构以 entry/bullet 为主，指南输入以 bullet 为主；直接给短 bullet 加一句 STAR 提示不足以保留完整项目，因此新增项目级 `project_story`，作为内容的可选版本化扩展。

建议在蓝图项目 entry 保存 `project_story`，包含 `schema_version`、`situation`（场景/问题）、`task`（角色/目标/约束）、`actions`（步骤/方法或工具/选择理由/难点处理/本人贡献）、`result`（交付物/验证方法/可选指标及条件）。另保存实际存在的素材、事实和画像要求引用及 AI 来源状态；项目 ID 与 bullet ID 由本地组装维护。结果指标区分 `target` 与有来源支撑的 `observed`，不强制虚构百分比或数字。无素材时明确为目标项目；有素材时保留真实部分，设计补充分开记录。

此扩展优先保存于现有版本内容 JSON，不新建项目库或向量库，不预先指定数据库迁移编号。实现时若改变数据库 schema 则增加 Alembic 迁移；仅 JSON 合同扩展需版本化读取与兼容测试。旧版本无 `project_story` 时仍可查看/导出；指南仅根据旧正文及其来源组织已有信息，缺失处列为准备问题，不反向改写或强制回填旧简历。

#### 蓝图项目写作

逻辑顺序：已保存目标画像与可选素材 → 按项目组织 STAR 说明 → 形成项目简介与行动/成果要点 → 本地保存 ID、引用与状态 → 内容检查 → 保存正文和项目说明。逻辑步骤不等于固定的模型请求次数，复用已有 Provider，不规定必须一次或多次调用。

写作输入明确目标能力、已有证据、可设计的部分和个人角色。S 说明问题为何存在；T 明确本人负责的目标与约束；A 展示解决问题的步骤、方法、取舍和难点，不能仅堆工具；R 交代产出及验证方式，目标指标说明测试条件或比较口径。项目规模和成果与角色、行动相称。不强制所有项目达到同样复杂度，不靠填入真实公司名或编造日期增强可信度。

本地保留 STAR 元素到可见简介/bullet 的映射，便于检查信息没有在压缩时消失。四要素在一个项目整体齐全，不要求每条 bullet 齐全或显示 S/T/A/R 标签。复用现有渲染承载自然语言正文，不把完整内部项目说明强塞进一页简历；若压缩丢失核心背景、任务或结果，应在文案阶段调整，不能只在指南中补齐便声称简历已经完整。求职版继续既有生成规则，不因蓝图新增目标而自动获得相同的已确认经历。

#### 内容检查与评审

确定性检查负责项目说明结构、必要信息非空、引用归属、可见元素映射和目标/实测状态；不能仅凭字段非空证明 STAR 质量。解释性模型评审使用同一项目说明与正文，指出背景与任务是否具体、行动能否支撑结果、技术路线是否合理、个人贡献是否清楚、指标是否可验证，以及跨项目重复/自相矛盾。问题定位到项目与要点，不填固定高分，不新增发布分数阈值。

缺少 STAR 必需信息、映射缺失、非法引用或把目标误标实测属于内容错误，沿用已有定向修复流程，只调整受影响内容。低分或风格建议仍不单独触发自动重写。不固定修复次数；无法消除错误时结束并明确失败，不能省略项目来规避问题。模型不可用时可提供基于同一输入的明确降级内容，仍需满足结构与状态要求，不能把通用占位项目称为高质量 STAR。

#### 两份指南共用项目上下文

指南读取各自已保存版本的正文、可见要点、目标快照、来源及对应 `project_story`。蓝图指南增加项目级 `project_cards`：项目概述、STAR 讲解提纲、关联 bullet ID、各关键行动的追问链、结果验证、知识准备和实践步骤。原有 bullet 卡保留逐条定位，可引用项目卡共享上下文，避免每条都重复同一段介绍。

每条追问链包含主问题、进一步追问、追问意图、回答要点、所需证据及常见误区，问题必须落在本项目的方法、选择、约束或结果上。例如结果包含响应时间目标时，应追问测量起止点、工况、采样或重复验证方法；未提供的信息应作为准备事项或建议方案，不能编造成已做过的实验。指南可解释专业知识与提出练习步骤，但明确区分建议和本人经历，不生成冒充完成的第一人称答案。

求职版指南按其实际要点提供个人贡献、方法、成果与证据准备；不读取不存在于该版本的蓝图成果充当本人经历。蓝图未来项目额外给出当前可诚实说明的边界、缺少的实践与应形成的材料。两份指南保持自我介绍、岗位题、动机、反问和检查表等既有内容；本轮不开发答题、自动评分或语音模拟。

#### 状态与展示

生成后保存正文、项目说明和来源绑定；项目说明的语义变化纳入内容指纹，使指南不能在项目依据已变化后仍被当作最新。单纯排版不改变内容指纹。兼容旧内容哈希规则，只有新合同内容采用新版本指纹；不能因部署就使历史正文或指南失效。

指南覆盖检查同时关注项目卡与所有可见 bullet，拒绝错误项目归属、重复卡片冒充覆盖、目标成果冒充实测。确定性补卡或模板回退说明实际降级来源，不能仅因覆盖率齐全就称为模型高质量结果。简历内容可交付后两份指南仍自动排队，不等待 PDF；指南失败不反向使简历失效。重复排队及旧任务晚完成沿用现有版本绑定规则，不借本轮重建统一任务平台。

前端只增加项目说明在指南中的组织、可定位的项目/要点关联及降级信息展示，复用既有简历预览和导出。成稿编辑、锁定、局部重生成等交互的新增/完善进入未来 TODO；既有调用必须安全保留新增项目说明，不能静默丢字段或留下与正文冲突的指南。

### 1. 所有生成都绑定 TargetProfile

新增 `target_profiles` 与 `target_profile_sources`。`mode=single_jd` 必须且只能关联一条当前用户可见的 Job；`mode=multi_jd` 必须关联 2–10 条。聚合结果保存为快照，要求项包含稳定 id、类别、优先级、出现频率以及每个来源的 `job_id + 原文片段`。服务端验证片段确实存在于对应 `raw_jd`，无来源的要求不得进入画像。

选择统一实体而不是为单 JD 保留独立生成路径，是为了让简历、质量报告和指南只维护一套合同。旧 Match 可作为单 JD 的辅助解释，但不再是创建双轨简历包的前置条件。

### 2. 复用并泛化 ExperienceEntry，ResumeFact 变为原子主张

不新增第二套素材表。扩展现有 `experience_entries`，使其用户侧名称为“简历素材”，`kind` 支持 education、internship、employment、project、research、competition、award、certificate、skill；新增 `details_json`、`clarifications_json`、`completeness_score` 和 draft/confirmed 状态。

`details_json` 统一保存背景、目标、个人职责、动作、工具、困难、取舍、结果、指标、团队边界和核验材料。上传解析或用户表单先创建素材，AI 只生成尚缺字段的追问。确认时服务端将素材拆为多个 `ResumeFact`，并为事实增加 `material_id`、`claim_type` 与 `evidence_json`；每个事实只表达一个可确认主张。旧 `linked_fact_id` 和旧事实继续读取，但新路径不再依赖一条素材只能映射一个事实。

选择扩展现有表而非迁移到全新材料表，是为了保留 `0008` 数据和隐私清理逻辑；用户隔离、范本不可直接确认及原始来源规则保持不变。

素材确认不是生成前置条件。未确认素材可作为文案参考，无素材也可基于有效画像扩写；素材采集阶段不猜填未知事实，文案阶段的 AI 补充则保持内部未确认状态，不自动确认或回写素材与事实库。

### 3. ResumeBundle 是双轨交付与异步状态边界

新增 `resume_bundles`，保存用户、基础简历、目标画像、事实快照、目标快照、模板快照、状态和生成元数据。每个 bundle 必须恰好有一条 `kind=submittable` 和一条 `kind=target` 的 ResumeVersion；ResumeVersion 新增 `bundle_id`、`target_profile_id`、`quality_report_json`、`content_hash` 和 `template_snapshot_json`，并允许多 JD 版本的旧 `job_id` 为空。

创建接口返回 `202` 与 bundle 状态。使用数据库中的 queued/generating/ready/degraded/failed 状态和带 claim token 的生成运行记录。本地开发由独立 Python worker 执行；小范围真实用户试用继续使用独立 worker 和 PostgreSQL 原子领取，不引入 Redis/Celery。重复请求由幂等键和请求哈希复用同一 bundle，中断任务通过租约、心跳和 claim token 安全恢复。

### 4. content_version=3 保留旧 kind，但强化逐条合同

继续使用 `submittable/target`，两版使用同一输入快照和内容合同，不规定合并或分别调用模型。职责分为三层：模型根据 JD 和素材选择内容、润色表达及提出扩写建议，返回结构化文案和经历、事实、岗位要求引用；本地组装层验证引用并维护内容状态；本地渲染层读取已保存内容及模板快照生成文件。模型不生成 HTML、CSS、DOCX、PDF、字号或分页，也不创建稳定 bullet ID 或决定锁定状态；局部重生成可回传已有 ID 作为定位引用。

本地组装层校验模型提出的经历引用与所引事实是否属于同一经历，禁止跨经历拼接；局部重生成固定原要点的经历归属。没有对应现有经历的 AI 建议作为独立建议条目保存，不强挂到现有经历。本地维护稳定 `id`、`achieved`、`locked`、`verification_status` 和固定章节顺序，并保存来源引用与 `new_claims`。有效来源 ID 只证明引用存在，不证明新增文案属实；来源不足或包含新增主张的内容保留 `ai_generated`、`achieved:false`，不得自动升级为用户已确认事实。

生成顺序为：本地整理证据与目标上下文 → 模型生成双版本文案 → 本地组装内容 → 确定性 Fact Guard 与内容门禁 → 必要时按硬门禁失败项定向修复 → 本地版面预判与渲染。`ai_expansion` 内容保留内部未确认状态，不自动成为用户事实。模型评审只补充解释性质量信息，不能放行硬门禁失败；低分、表达重复或相关性建议不单独触发自动重写，用户可主动选择重生成。修复仅影响失败项涉及的未锁定内容；无法修复时结束并回退或失败，不无限循环。模型不可用时仅在本地基础版通过内容门禁后标为 `degraded`，否则生成失败。

局部重生成按 bullet/section/all 三种 scope 工作，locked bullet 不被全局重生成覆盖。任何用户编辑或重生成都会更新内容哈希、重新执行门禁，并把绑定旧哈希的指南标为 stale。

### 5. 质量分为硬门禁与解释性评分

内容门禁在组装阶段检查来源 ID 与经历归属、结构、kind/achieved 语义和目标要求覆盖；字符数与估算行数仅用于排版预判。文件门禁在渲染后检查实际分页、裁切、字体、文本层及正文完整性，不能以内容预判代替。允许 AI 扩写时，事实不足仅形成内部状态或质量提示，不得把 AI 文案当作已确认事实。解释性评分覆盖目标相关性、具体性、个人贡献、信息密度、可读性、ATS 和面试可辩护性，保存分项分数、问题和修复历史。

简历内容通过内容门禁后可进入 ready；使用本地基础文案或确定性评审回退时进入 degraded 并明确说明来源。最终内容门禁失败必须为 failed。各格式仅在自身文件门禁通过后交付，PDF 不可用或 QA 失败不改变已完成的简历状态。解释性评分用于定位改进问题，不允许为了提高分数放松硬门禁。

### 6. 一份版本化模板快照，不建模板目录

首版模板配置固定为 `classic-navy-ats-v2`，由应用内版本化 JSON 提供，并在 bundle/version 上保存快照。当前只有一套模板，因此不创建 `resume_templates` 表或模板后台；以后增加第二套模板时再引入目录。

分区顺序固定为求职方向、教育、实习/工作、项目/科研/竞赛、奖项证书、技能。蓝图未来项在正文附上轻量上标 `*`，页脚统一解释；真实版无标记。HTML、DOCX 与 PDF 均由本地模板代码从同一内容和 profile 生成，渲染及重复导出不得调用模型。HTML 是打印预览与 PDF 的规范布局，DOCX 从同一内容和 profile 生成。PDF 优先由固定 Chromium 打印 HTML；不可用时可由 LibreOffice 转换 DOCX，但仍须通过页数、字体、文本层和内容计数 QA。两者都不可用时 HTML/DOCX 可用，PDF 返回明确依赖错误；PDF 转换或 QA 失败不得使已完成的简历版本失效。

本地指应用服务端或 worker 中的渲染代码。渲染器不改写正文、截断句子或静默删除要点。实际检查确认正文容量溢出时，只在保存的模板允许范围内调整间距，不缩小字号；模板未定义调整范围时保持原值。仍超页则拒绝 PDF 并返回页数及可定位的溢出内容：生成流程可交回内容阶段缩写未锁定要点，已有版本的下载只报告问题，由用户主动编辑或重生成。保留锁定要点的内容、位置和经历归属；无法容纳或调整稿未通过内容门禁时保留原内容并说明原因。正文修改后重新校验、保存内容哈希并使旧指南过期；单纯排版调整不改变内容哈希。所有格式均渲染最终保存的同一内容。

内容溢出与 PDF 技术故障分开处理，不能只凭超页就自动重写。转换器缺失返回 `PDF_CONVERTER_UNAVAILABLE`，物理检查失败返回 `PDF_QA_FAILED`，转换执行异常返回明确的独立导出失败原因。字体、Unicode、裁切或文本丢失等技术问题只修复本地导出，不调用文案模型，不改变保存内容、哈希或指南状态。

固定 Chromium 和字体环境下，HTML 打印预览与 PDF 使用相同布局；DOCX 保证正文、章节顺序和标记一致，不承诺不同 Word 软件下像素级排版一致。LibreOffice 备用 PDF 遵循相同内容和物理 QA 要求，不承诺与 Chromium 像素级一致。

### 7. InterviewGuide 与旧 Interview 分离

新增 `interview_guides`，绑定 `resume_version_id`、`target_profile_id`、版本内容哈希、guide kind、内容和质量报告。两版内容门禁通过、bundle 为 ready 或可交付 degraded 后，分别自动排队生成指南，不等待 PDF、不改成打开时才生成；指南失败不反向使简历失效。求职版覆盖每个可见 bullet 的主问、连续追问、六段式讲法、个人边界、核验材料和危险说法，并补充 60/90 秒自介、JD 题、反问和检查表。蓝图版覆盖所有可见 bullet，未来项使用风险卡、当前诚实边界和补证要求，不生成冒充完成的答案。

每张卡引用 bullet id 及版本中实际存在的素材/事实/目标来源，服务端要求可见 bullet 覆盖率为 100%。无事实来源的 AI 扩写卡仍须绑定该 bullet 并保留未确认语义，不得伪造来源或将建议写成已发生的用户经历。旧 Interview、答题和顾问评分接口保留，只从新导航移除。

### 8. 新工作台渐进接管用户入口

新增 `/app/resume-studio`，以目标、素材、双版本、导出、指南五个连续区域组织流程；允许上传或空白建档、逐条查看来源、锁定、重生成、排序、撤销和版本对比。普通用户主导航只保留工作台、指南和账户设置；旧 URL、API 和管理角色页面继续可访问，避免破坏已有演示与数据。

自助预览和导出只要求 Guard 与质量硬门禁通过，不要求顾问批准。旧投递队列若继续使用 ResumeVersion，仍可保留其原有审核要求，不反向阻塞新工作台导出。

### 9. 规格优先级通过新增裁决而非改写历史

在 `PROJECT_SPEC.md` 新增方向裁决章节，并新增 `docs/plan-resume-interview-core.md`。`AGENTS.md` 将新计划置于旧 `plan-target-resume-loop.md` 之前；旧文档保留为历史实施记录。`stabilize-uncommitted-surfaces` 保留但标为暂停，不执行其校招和模板目录任务。

### 10. 小范围真实用户试用使用持久任务和同域名部署

试用环境由 Caddy、React 静态站点、FastAPI API、独立 Python worker、PostgreSQL 和私有 S3 兼容对象存储组成。API 与前端共用域名，API 只负责鉴权、事务写入和查询；模型生成、解析、指南与 PDF 由 worker 执行。生产不使用 SQLite 或临时本地文件回退，本地开发仍保持无 Docker、无 Redis 的轻量路径。

新工作台使用统一任务合同提交耗时操作。任务保存输入快照、资源归属、幂等键、状态、阶段、claim token、租约、心跳、尝试次数、公开错误和结果资源。worker 默认每 15 秒续租，90 秒未续租后可重新领取；所有进度和结果提交均校验 claim token。相同幂等键与输入复用原任务，相同键与不同输入返回冲突。

邀请注册与邀请码核销在同一事务内完成。创建任务时预留额度，成功或可交付降级后结算，失败释放；同一用户的并发 AI 任务受限。草稿、任务、简历、指南和导出状态均从服务器恢复，前端使用渐进轮询并对版本冲突、登录过期、网络超时和分资源失败给出可恢复操作。

Storage Provider 扩展受控读取与下载，生产文件只进入私有对象存储。每日备份默认保留 14 天，邀请开放前完成恢复演练，并监控 API、worker、队列、失败率和模型用量。支付、公开注册、邮件通知和高可用集群不在本阶段。

## Risks / Trade-offs

### 2026-09-09 文案与排版修订

本修订细化权威实施计划的“本地整理上下文、模型文案、本地渲染”职责，保持 AI 扩写、异步任务、锁定和指南规则。当前质量基准仅验证基础版硬门禁，不能证明专业文案或视觉质量；本节设计尚待实施与验收。

1. **目标上下文**：粘贴 JD 时不提交“目标岗位/目标公司”作为显式业务值；保留用户真实输入，缺失时从原文提取，无法提取则保留未知。生成快照包含岗位标题、公司、JD 原文及 requirement 的证据、频次和优先级；写作输入保留必要原文上下文，不能只传扁平要求列表。
2. **经历与选材**：按 `material_id` 整理背景、个人职责、动作、工具、结果、指标、取舍与核验信息，保留 `claim_type`、证据和确认状态。先用本地关键词相关性排序选择项目/工作素材，初始以最相关 3 段为候选预算；教育、必要资质、锁定内容和高优先级要求覆盖单独保留，不能被 top-k 截掉。同分排序稳定，未入选及未覆盖原因进入内部简报。不强制增加用户表单字段。
3. **写作简报**：`writing_brief` 保存每段经历对应要求、事实引用、2–3 个写作角度和篇幅预算。写作要求呈现具体问题、本人动作、方法与产出，避免泛泛堆技能和重复句式；缺少指标可以写具体交付物。草稿、事实与 AI 补充分开标识；无素材仍可生成。简报及策略版本进入任务快照和请求哈希。局部重生成使用原经历、锁定内容和相应要求，不重新混入不相关项目。
4. **项目原型实验**：先用 12–24 条本地版本化 JSON 原型，字段含 id/version、岗位方向、适用技能与难度、问题场景、任务步骤、工具与产物、指标槽位、核验材料、示例句、来源说明。模型可协助起草，由人工核对专业合理性；不收集整份真实简历。选入最多 2 条相关原型作为独立参考，并保存命中内容与版本；原型 ID 不进入 `source_fact_ids`。原型数值、组织、日期不能直接成为用户事实，衍生扩写仍按既有 `ai_generated/achieved:false` 合同处理。本修订不恢复“仅已确认事实才可生成”的限制。
5. **文案验收**：首次生成与重生成均运行解释性 critic，保存具体受影响 bullet 和建议；缺失评分维度显示未评估，确定性检查不冒充模型分数。评分低不自动循环重写。准备至少 12 个虚构案例，四方向各含丰富、稀疏和空白素材，对比 A 当前链路、B 简报与选材、C B 加原型；固定模型及参数，每例重复 3 次并打乱顺序盲评。采用现有五项维度，各方向各维度平均至少 4/5；同时记录重复表达、错误归属、扩写误标事实、修改量、耗时和可获得的 token 用量。原型是否进入默认链路依据 C 相对 B 的质量、修改量和成本记录决定；无明确收益则保留 B，数据库化不属于本轮。
6. **本地模板与预览**：A4 保持 210×297mm。浏览器 CSS px 与 PDF pt 不混用；预览按容器宽度等比缩放完整页面，打印不继承预览缩放。同一模板新增 `spacious/balanced/compact` 间距档位，不缩小字号、不删改正文；按固定 Chromium 和字体实际测量选取可容纳正文的最宽松档位。档位允许范围、选定值及渲染模板版本可复现；旧快照不补套新档位。新视觉设计发布新模板版本并保留旧渲染版本。预览与 Chromium PDF 使用同一选定配置；LibreOffice 独立通过 QA，不承诺像素一致。模型不输出布局枚举或任意 CSS，离线 AI 辅助设计的模板经人工验收后固化。
7. **视觉验收**：至少 12 份固定虚构正文覆盖短中长、长中英文标题、联系方式换行、多经历、技能和蓝图页脚。检查桌面及窄屏完整预览、标题/日期对齐、层级、留白、分页与文本完整性，保留经人工认可的截图基线。真实 Chromium PDF 必须通过全部物理检查；实际走哪个转换器须记录，备用转换成功不能证明 Chromium 路径通过。视觉问题与文案问题分别定位。

实施先完成目标上下文和预览尺寸修复，再完成简报、选材与文案/视觉基准，最后评估项目原型增益。相关测试随实施执行，最终运行完整测试和构建；仅有代码与验收证据的任务可勾选。

- [自动修复仍无法产生可交付内容] → 保留问题摘要，仅交付通过门禁的结果；本地回退明确 degraded，最终内容门禁失败明确 failed。
- [四类理工科质量差异大] → 使用共享结构合同加四类独立虚构基准；未通过某类基准时不得宣称该类达到高质量。
- [原子化事实增加填写负担] → 先解析/预填，再只追问影响表达质量的缺口，允许保存草稿。
- [单页目标与信息完整性冲突] → 简历保持单页，蓝图目标说明和详细质量报告作为独立附件，不挤入正文。
- [PDF 在不同机器上字体与分页波动] → 快照保存布局参数，部署安装固定字体与 Chromium，并以实际 PDF QA 作为发布门禁。
- [旧流程与新工作台长期并存] → 新接口只做兼容读取，导航和验收只围绕新主流程；后续独立 change 再移除旧能力。
- [页脚标记可能被用户删除] → 系统导出的蓝图始终重新渲染标记；用户修改外部文件不被系统认证为真实版本。

## Migration Plan

1. 先修复当前前端构建并提交仓库忽略边界，建立可靠基线。
2. `0009_add_target_profiles_and_material_claims` 新增目标画像/来源并扩展素材与原子事实；回填旧 ExperienceEntry 状态与旧事实兼容字段。
3. `0010_add_resume_bundles_and_interview_guides` 新增 bundle、运行记录和指南，并扩展 ResumeVersion；旧版本保持原值，不强制回填 bundle。
4. 上线新 API 和工作台但保留旧入口；虚构种子数据同时覆盖单 JD、多 JD 和四类专业。
5. 完成质量与导出门禁后将普通用户默认入口切到工作台，并隐藏非核心导航。
6. 回滚时先恢复旧导航，再降级 `0010` 和 `0009`；旧 Job、Resume、ResumeFact、ResumeVersion 与 Interview 数据保持可读。
